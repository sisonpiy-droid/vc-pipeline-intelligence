Data Flow (step by step)

  1. Cron (Mon+Thu) or manual trigger starts a run; one queue row per investor is created.
  2. An invocation claims 3 investors at a time; unfinished work is handed to a fresh invocation.
  3. Research: Tavily search for the last 30 days → fetch each page → read its own publication date.
  4. Validate: investor named? inside the window? dates consistent? duplicate event? else reject with a reason.
  5. Gemini Flash classifies and judges relevance; its quote must exist verbatim in the page.
  6. Scoring engine computes the 0–100 score, action and explanation (deterministic).
  7. One transaction as role vc_refresh: save evidence + coverage + audit, update only the 4 columns.
  8. Failures keep the previous score and are recorded; the run is “succeeded” only when every item is done.
  9. The dashboard derives states (active / failed / partial / stale / quiet) at read time.
